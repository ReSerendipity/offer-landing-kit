# 社保断档测算 · 最小核对路径（可重跑）

> 适用范围：`index.html` 中「模块2：断档预警引擎（月粒度）」，即 `calcSocial()` / `monthIdx()` / `runDemoSocial()`。
> 这块结果影响落户 / 购房资格判断（README「免责声明」已就此声明），因此**改动它必须跑本文件**，而不是只靠肉眼看界面。
> 本文件只描述**如何验证**，不定义业务口径；业务口径的唯一来源是 README 模块表 + 页面「口径说明」文案。

## 0. 什么改动要跑本核对

- `calcSocial()` 内任何计算、分支、文案变更（含风险等级阈值判断）。
- 边界月两个复选框（`s-leave-same` / `s-join-same`）的默认值或语义变更。
- `CITY` 门槛表、补缴估算（`s-base` / `s-rate`）相关变更。
- `runDemoSocial()` 演示数据变更（会连带改变 README 里「断档 2 个整月」的声明）。

清单文案、台账里程碑等非断档逻辑不需要跑本核对。

## 1. 口径不变式（改代码前后都必须成立）

代码锚点写在右侧，改动后请回来看这一栏是否还对得上。

| 编号 | 不变式 | 代码锚点 |
|---|---|---|
| I1 | **月粒度折算**：断档只按「整月」计数，日期里的「日」不参与断档月数计算，只用于「自然日（参考）」 | `monthIdx(d.getFullYear(), d.getMonth())`；`days = Math.round((d2-d1)/86400000)` |
| I2 | **边界月由用户确认**：离职当月 / 入职当月各由一个复选框决定是否计入缴纳；两框方向相反——勾选「入职当月不缴」使 `gap` **+1**，勾选「离职当月不缴」使 `gap` **−1**（详见 §5） | `leaveSame` / `joinSame`；`+ (leaveSame ? 0 : 1)`、`+ (joinSame ? 0 : 1)` |
| I3 | **断档月数公式**：`gap = max(0, 入职缴款月序号 − 离职缴款月序号 − 1)`，两端已缴月本身不计入断档 | `var gap = joinPay - leavePay - 1; if(gap < 0) gap = 0;` |
| I4 | **补缴估算**：`cost = gap × 月缴费基数 × 费率%`，四舍五入到元；费率 < 1 时按小数比例自动 ×100 | `var cost = gap * base * rate`；`if(rv < 1) rv = rv*100` |
| I5 | **补缴不救连续年限**：只要 `gap > 0`，结论文案必须说明「连续缴纳已中断（清零）」且「多数城市规定补缴不计入连续年限」，补缴估算只是金额参考、不消断档 | `else if(gap < threshold)` 分支文案 |
| I6 | **风险三档**：`gap === 0` → 无断档（绿）；`0 < gap < 门槛` → 已断缴（琥珀）；`gap >= 门槛` → 超门槛（红）。边界归入「超门槛」 | `if(gap === 0)` / `else if(gap < threshold)` / `else` |
| I7 | **异常分支**：入职日早于离职日 → 风险等级显示「异常」、仪表盘置红、断档/自然日/补缴三项均显示「—」、不渲染月历、`last_risk` 置 null（全局状态条回到「未测算」） | `if(d2 < d1){ … }` |
| I8 | **缺输入分支**：离职日或入职日任一为空 → 提示「请填写离职日与入职日。」，结果区归零、`last_risk` 置 null | `if(!leave || !join){ reset(…) }` |
| I9 | **全局联动**：入职日一处填写即写入 `dzb2_join_date` 并同步断档模块与台账模块；断档结果写入 `dzb2_last_risk` 供页首状态条复用 | `setJoinDate()` / `LS.set('last_risk', gap)` |
| I10 | **月历渲染**：跨度 ≤ 14 个月时逐月铺满；> 14 个月折叠为「首 7 月 + …N 个月… + 末 6 月」 | `var show = total <= 14` |

## 2. 前置准备（浏览器，零依赖）

1. 直接用浏览器打开 `index.html`（无需服务器；线上核对换 `https://reserendipity.github.io/offer-landing-kit/`）。
2. 清一次本机残留状态，避免上一次的勾选被 localStorage 带进来：
   F12 控制台执行 `Object.keys(localStorage).filter(k=>k.startsWith('dzb2_')).forEach(k=>localStorage.removeItem(k)); location.reload()`
3. 每个用例都**以固定绝对日期**填写，断档模块内改完日期会触发 `change` 自动测算；若未刷新，点「测算断档风险」。
4. 涉及复选框的用例跑完，把两个边界月复选框**勾回默认（都勾选）**再做下一个用例，否则脏状态会污染后续期望值。

手算公式（与 I2/I3 逐字一致，用于交叉核对表格）：
`leavePay = 年×12 + (月−1) + (离职当月未缴 ? 1 : 0)`；`joinPay = 年×12 + (月−1) + (入职当月未缴 ? 1 : 0)`；`gap = max(0, joinPay − leavePay − 1)`；`补缴 = gap × 基数 × 费率%`。月历格子数 = `joinPay − leavePay + 1`。基数 18000 / 费率 38.5% → **每个断档整月 ￥6,930**。

## 5. 已知的显示特性与边界月方向（别当 bug 报，也别顺手「修」出口径变化）

- **边界月两框方向相反（重要不变式）**：`leavePay = 离职月 + (离职当月未缴 ? 1 : 0)`、`joinPay = 入职月 + (入职当月未缴 ? 1 : 0)`，而 `gap = joinPay − leavePay − 1`。因此取消「入职当月缴」让 `gap` **+1**（C2），取消「离职当月缴」让 `gap` **−1**（C3，离职当月被移出月历），两者同时取消则相互抵消回到 C1（C3b）。这是代码的真实口径，无论是否符合直觉，改动前后都必须以此为准；若有人把符号「修反」，C2/C3/C3b 三行会立即对不上。
- 「入职当月新公司开始缴纳」这个复选框**不判 15 号**：勾选即「入职当月缴」，取消即「次月缴」。界面副标题里「15 号前入职当月缴」是对该惯例的人类可读解释，不是代码分支。改文案可以，改成真的按日判定就是口径变更，必须重跑全表并同步 README。
- 同月衔接（C6）时唯一一格显示「入职续缴」而非「缴纳」，断档为 0、结论仍为无断档。
- C7：自然日 > 0 而断档 = 0 是「整月断档」口径的必然结果，风险等级以整月数为准。
